# Лингвич

Сайт и учебная платформа языковой школы: публичный сайт, запись на занятия,
личные кабинеты ученика и преподавателя, CRM владелицы.

Django 5.2 LTS + PostgreSQL, серверный рендеринг, без сборки фронтенда. Весь интерактив —
на ванильном JS поверх `fetch`; страницы не перезагружаются, но при выключенном
JS формы продолжают работать обычным POST.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # локально можно не заполнять: будет SQLite
python manage.py migrate
python manage.py load_placement_questions   # 50 вопросов теста уровня
python manage.py seed_catalog               # языки, курсы, тарифы, офисы
python manage.py seed_demo                  # демо-данные, чтобы всё было видно
python manage.py runserver
```

После `seed_demo` доступны демо-аккаунты (пароль у всех `linguich2024`):

| Роль | Логин |
|---|---|
| Владелица (CRM + преподавание) | `owner@linguich.ru` |
| Преподаватель | `anna@linguich.ru` |
| Ученик | `+79130001001` |

Вход работает и по email, и по телефону — ученики стабильно помнят что-то одно.

### Открыть в PyCharm

1. **File → Open** и выбрать папку проекта.
2. **Settings → Project → Python Interpreter → Add → Virtualenv Environment**,
   `Base interpreter` — Python 3.11+. PyCharm сам предложит поставить
   зависимости из `requirements.txt`.
3. **Settings → Languages & Frameworks → Django**: включить Django Support,
   `Django project root` — корень проекта, `Settings` — `config/settings.py`,
   `Manage script` — `manage.py`. После этого заработают автодополнение
   в шаблонах и переход по `{% url %}`.
4. Конфигурация запуска: **Run → Edit Configurations → + → Django Server**,
   host `127.0.0.1`, port `8000`. Команды `migrate`, `seed_demo` и остальные
   удобно звать через **Tools → Run manage.py Task**.
5. Тесты: правой кнопкой по папке `apps` → **Run 'Tests in apps'**.

`.idea/` намеренно не в репозитории — это локальные настройки конкретной
машины. Общие правила форматирования лежат в `.editorconfig`, PyCharm читает
его сам.

## Что где лежит

```
apps/
  accounts/      пользователи и роли, вход по email/телефону, привязка Telegram
  school/        публичный контент: языки, курсы, акции, отзывы, заявки (лиды)
  scheduling/    группы, расписание, окна записи, уроки, посещаемость
  learning/      программы, модули, темы, материалы, домашние задания
  billing/       тарифы, абонементы, платежи, списания уроков
  placement/     адаптивный тест уровня
  notifications/ очередь уведомлений и её отправка
  cabinet/       представления кабинетов (своих моделей нет)
config/          настройки, URL-роутинг
static/css/      дизайн-система: tokens → base → components → site/cabinet
static/js/       app.js (ядро), quiz.js (тест), booking.js (запись)
templates/       public/, cabinet/, components/, registration/
```

### Четыре роли, один аккаунт

`User.role` — `student` / `teacher` / `admin` / `owner`. Владелица тоже ведёт
уроки, поэтому `user.is_teacher` истинно и для неё: все преподавательские
экраны доступны без дублирования кода, а сверху добавляется раздел «Школа»
с CRM.

Администратор — помощник в офисе. `user.is_manager` (администратор
и владелица) открывает повседневную работу CRM: заявки, ученики, платежи,
группы. `owner_required` оставляет владелице то, что помощнику знать
незачем: состав сотрудников и зарплаты.

### Доступ выдаёт школа, а не ученик

Свободной регистрации нет (`PUBLIC_REGISTRATION_ENABLED=False`): аккаунт
заводит администратор или владелица, а логин с паролем генерирует
`apps/accounts/provisioning.py`. Логин — транслит фамилии (`ivanov`,
`ivanovm`, `ivanov2`), потому что его диктуют по телефону. Пароль
случайный, но без символов, которые путают на слух и на письме.

Отсюда поле `username`: у школьника может не быть ни почты, ни своего
телефона, а войти ему всё равно нужно. Войти можно любым из трёх —
логином, почтой или телефоном.

Выданный пароль знает не только его владелец, поэтому он временный:
`must_change_password` закрывает кабинет до замены.

## Ключевые решения

**Индивидуальные занятия — это группа на одного.** `Group.capacity == 1`.
Благодаря этому расписание, домашки, списания и отчёты работают одним кодом
и для групп, и для индивидуальных учеников.

**Запись и посещаемость — одна строка.** `LessonParticipant` хранит и факт
брони, и итоговый статус (был / не пришёл / отменил заранее). Не нужно
сверять две таблицы, чтобы понять, списывать занятие или нет.

**Два независимых счётчика денег.** У школы их правда два:
- *сколько должен* = сумма выданных абонементов − сумма платежей;
- *сколько уроков осталось* = купленные уроки − списанные.

Выдача абонемента создаёт начисление, платёж его гасит, проведённый урок
уменьшает баланс занятий. Отсюда честный список должников без ручного счёта.

**Отмены по правилам школы.** Раньше `FREE_CANCELLATION_HOURS` (по умолчанию 12)
отмена бесплатна, позже — занятие списывается. Отмена со стороны школы не
списывает ни у кого.

**Уведомления только в очередь.** Запрос никогда не ходит в SMTP или Telegram
напрямую — он кладёт запись в `Notification`, а разбирает очередь cron. Упавший
почтовый сервер не может сломать запись на урок. `dedupe_key` делает постановку
идемпотентной: планировщик напоминаний можно запускать хоть каждую минуту.

**Защита форм — слоями, без капчи.** Капча стоит конверсии, а ботов
останавливает ненадолго. Вместо неё четыре дешёвых приёма в
`apps/school/antispam.py`: поле-приманка, подписанная метка времени
(форму нельзя отправить быстрее человека и нельзя переиспользовать),
лимит заявок с одного IP за час и гашение повторов по телефону. Живой
посетитель ни одного из них не замечает. Пороги — константы в начале
модуля; выключить всё разом можно `LEAD_ANTISPAM_ENABLED=False`, но это
только для отладки самих форм.

**Тест уровня действительно адаптивный.** Четыре вопроса на ступень CEFR, затем
шаг вверх, вниз или остановка. Сильный ученик доходит до C1 за ~12 вопросов,
слабому не выдают двадцать заданий, которые он не прочитает. Итоговый уровень —
самая высокая ступень, где взято не меньше половины. Результат раскладывается
по навыкам (грамматика, лексика, чтение, речевые ситуации) и превращается
в заявку в CRM.

## Регулярные задачи (cron)

```cron
# Отправка очереди уведомлений
* * * * *  cd /path/to/linguich && .venv/bin/python manage.py send_notifications

# Постановка напоминаний об уроках на ближайшие дни
*/15 * * * *  cd /path/to/linguich && .venv/bin/python manage.py schedule_reminders

# Материализация занятий групп по недельному расписанию
0 3 * * *  cd /path/to/linguich && .venv/bin/python manage.py generate_lessons --weeks 6
```

Все три команды идемпотентны — повторный запуск ничего не дублирует.

## Telegram-напоминания

Отправлять сообщения можно через **любой** бот школы: для этого достаточно
токена в `TELEGRAM_BOT_TOKEN`. Отправка через Bot API не мешает боту жить
своей жизнью. Сложность одна — узнать `chat_id` ученика: апдейты Telegram
отдаёт кому-то одному.

**Если бот у школы уже есть** (он держит long polling — вебхук ставить нельзя):
задайте общий секрет в `TELEGRAM_LINK_API_KEY`, и пусть бот на `/start <код>`
дёргает наш эндпоинт:

```python
# в обработчике /start вашего бота
requests.post(
    "https://linguich.ru/accounts/telegram/link/",
    json={"code": code, "chat_id": message.chat.id},
    headers={"X-Api-Key": TELEGRAM_LINK_API_KEY},
    timeout=5,
)
```

Ученик берёт ссылку с кодом кнопкой «Подключить Telegram» в профиле —
она открывает бота и сразу подставляет `/start <код>`.

**Если своего бота нет** — платформа примет апдейты сама:

```bash
curl -F "url=https://linguich.ru/accounts/telegram/webhook/" \
     -F "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
     https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook
```

Использовать оба способа одновременно не нужно. Без токена система работает
как обычно: Telegram-канал пропускается, уведомления остаются в кабинете
и уходят на почту.

### «Уведомления не приходят»

Причин ровно три, и снаружи они выглядят одинаково. Разделяет их команда:

```bash
python manage.py check_notifications          # что настроено и что в очереди
python manage.py check_notifications --send-test   # пробное сообщение владелице
```

1. **Очередь никто не разбирает** — видно по «просрочены больше 5 минут».
   Не установлен cron: `crontab deploy/crontab`.
2. **Слать некому** — у получателя не привязан Telegram. Пока
   `telegram_chat_id` пуст, сообщение в этот канал даже не ставится
   в очередь: канал выбирается в момент постановки, а не отправки.
3. **Отправка падает** — токен неверный или бот заблокирован получателем.
   Тогда в «Последней ошибке» будет текст от Telegram.

## Дизайн-система и брендбук

Всё перекрашивается из одного файла — `static/css/tokens.css`. Там же светлая
и тёмная темы: тёмная собрана отдельно, а не инверсией, и переключатель темы
побеждает системную настройку в обе стороны.

Из брендбука взяты:

| Элемент | Значение | Где лежит |
|---|---|---|
| Фирменный синий | `#008CD2` (снят пипеткой со знака) | `--brand-500` в `tokens.css` |
| Чёрный логотипа | `#2B2B2B` | `--ink` |
| Гарнитура логотипа | ITC Officina Sans Black | `static/fonts/` |
| Знак | векторизован из логотипа | `static/img/logo-mark.svg` |

Знак — точная трассировка логотипа в SVG (12 КБ), поэтому он чёткий на любом
размере и не размывается на ретине. Он всегда фирменного синего, в том числе
в тёмной теме — так требует брендбук; выворачивается только текст логотипа.

Для фавиконки используется упрощённый вариант (`static/img/favicon.svg`):
детальная карта материков на 16px превращается в кашу, поэтому там глобус
сведён к меридианам. Это стандартная практика, а не отступление от брендбука.

Лок-ап собирается в `templates/components/logo.html` и принимает подпись:
в шапке «языковая школа», в подвале полная «школа европейских и восточных
языков», в кабинете «личный кабинет».

Обновление после первой установки:

```bash
ssh linguich@сервер
cd /srv/linguich && ./deploy/deploy.sh
```

## Что осталось решить

- **Онлайн-оплата.** Сейчас платежи заносит владелица, система считает долги
  и выручку. Поля под эквайринг (`Payment.provider`, `provider_payment_id`)
  уже есть — подключение ЮKassa сводится к одному вебхуку.
- **Онлайн-уроки.** Платформа хранит ссылку на класс (у урока, у группы или
  постоянную у преподавателя) и собирает вокруг неё материалы и домашки.
  Своя видеосвязь не строилась намеренно: это отдельный продукт, а Zoom/Jitsi
  решают задачу лучше и бесплатно.
- **Фото владелицы на главной.** Блок «слово основателя» уже собран и включён:
  текст и должность заполнены, ждёт только фотографию. Загружается в админке —
  *Настройки сайта → Основатель: фото*, вертикальный кадр 4:5. Пока фото нет,
  на его месте буква-заглушка; чтобы убрать блок целиком, достаточно очистить
  поле «Основатель: обращение».
